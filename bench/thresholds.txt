# Benchmark regression thresholds (#31). Policy upper bounds on the MEDIAN of
# each metric over the plain passes (latency) and the counted passes
# (syscalls/req), as printed by bench/summarize.sh. bench/regress.sh fails when
# a median exceeds its bound.
#
# Calibrated to the P4 gate run (bench/RESULTS.md, "P4 gate calibration"):
# FreeBSD 15.1, Zig 0.15.2 ReleaseSafe, SYSCALLS=truss, 5 reps, quiet host
# (load1 4.91 <= 0.5*20, ip netisr Len 0, QDrops delta 0). The gate counts with
# truss, so the bounds are set against truss medians, not the older DTrace
# baseline numbers.
#
# Syscalls/req is deterministic (run-to-run spread < 0.01), so its bound sits
# roughly 0.5-0.9 above the measured median: a regression of about one syscall
# per request trips it. This catches losing an adopted optimization (echo1
# 3.009 -> ~4 without readiness counts; wake 4.232 -> ~8 back on the pipe).
# Latency is noisy on the shared host, so
# its bound is roughly 2x the measured median: a coarse guard against gross
# regressions, not run-to-run noise. Accept results only from a quiet host
# (bench/quiet.sh).
#
# scenario  metric        median_max
echo1       syscalls/req  3.5
echo1       p50_us        90
echo1       p99_us        350
echo16      syscalls/req  2.6
echo16      p50_us        280
echo16      p99_us        650
storm16     syscalls/req  6.0
storm16     p50_us        1100
storm16     p99_us        2500
bulk4       syscalls/req  6.5
bulk4       p50_us        15000
bulk4       p99_us        25000
wake        syscalls/req  5.0
wake        p50_us        25
